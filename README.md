# 统筹区域创新联合投入协作基础服务

本项目提供科技创新协作场景共用的服务端基础能力：在科研机构、创新节点、操作者、结构化资料、角色权限、请求幂等、SQLite 事务与哈希串联审计之上，实现**区域科技创新中心交叉学科平台的联合投入与履约服务**。重大项目、科研证据、成果转化和国际合作等领域可以在这些稳定边界上继续扩展。

## 解决的问题

三个区域科技创新中心共建交叉学科平台时，同一首席专家、同一台设备常被各地重复计入自己的配套承诺，企业资金又附带不同的成果落地条件。直接汇总会高估平台能力，并在考核时引发归属争议。本服务把"承诺"与"真实可分配额度"分离：

- **章程版本冻结**：合作章程、机构上限、优先冲突规则按版本登记；承诺完成全部会签时快照当时生效的章程，后续裁定结果不被新章程改写。
- **会签才占额**：承诺只有在各方会签完成后才占用可分配额度；草稿、会签中、已撤回的承诺一律不占额。
- **冻结优先规则裁定**：同一人才/设备/资金跨计划被重复主张时，按计划优先级、会签完成时间的冻结顺序在资源容量与机构上限内裁定，低优先级承诺被压缩为部分额度或阻塞。
- **反拆分**：可分配额度按机构逐笔全额汇总核算（人才工时/设备时段按月、资金按来源累计），把一条承诺拆成多条不能绕过机构上限。
- **只重算未来**：人员离任、设备停机/恢复、资金分期延期、成员退出，都以生效日期为界只调整当前及未来义务；已完成的投入（履约）与已固化的成果分配永不回写。
- **历史复原**：所有状态变化都是追加式流水（占用/回填/释放、生命周期、分期事件），可按任意历史日期复原当时有效的章程、成员资格与承诺账。

## 领域对象

- 平台 `platform`、成员资格 `membership`（含地方配套/落地条件 `local_conditions`）
- 章程版本 `charter`（上限 `caps`、优先规则 `priority_rules`、退出后成果再分配规则）
- 人才 `person`（月度可投入工时）、设备 `equipment`（月度可用时段）、资金来源 `fund_source`（总额、用途与落地限制 `restrictions`）
- 计划 `plan`（平台内唯一优先级）、里程碑 `milestone`（结构化真实资源需求）
- 承诺 `commitment`（资源、数量、月份/时间窗、资金分期、会签方清单）、会签 `signoff`
- 额度流水 `allocation`（grant/backfill/release）、履约流水 `performance`
- 异动：人员离任、设备停机/恢复、资金分期延期/到账、成员退出
- 成果权益方案（版本化）与里程碑成果固化 `outcome award`

## 理事会视图

- `GET /jv/milestones/{id}/readiness`：里程碑是否具备真实资源、按资源类型/月份的覆盖、**缺口及可补足机构与余量**、以及任一在保成员退出时对后续权益和未来义务的模拟影响。
- `GET /jv/platforms/{id}/snapshot?as_of=YYYY-MM-DD`：复原历史日期的章程、成员与承诺。
- `GET /jv/commitments/{id}?as_of=...`：单条承诺的会签、占用/释放流水、履约、当时状态。

## 目录

- `src/science_strategy_foundation/`：领域模型、SQLite 存储、权限服务、审计链、HTTP 路由、联合投入服务和离线验收；
- `tests/`：基础规则、事务边界、接口路由、联合投入不变量和端到端验收测试。

## 环境

- Linux
- Python 3.11 或更高版本
- 运行时仅使用 Python 标准库和 SQLite

## 测试

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

## 构建检查

```bash
python3 -m compileall -q src tests
```

## 离线验收

```bash
PYTHONPATH=src python3 -m science_strategy_foundation.acceptance
```

验收命令会在临时 SQLite 数据库中登记科研机构、操作者、创新节点和业务资料，并跑通一条联合投入链（章程、成员、同一专家跨区重复计入、会签占用、优先裁定、历史复原），核对幂等回执与审计链，成功时输出一行 `status` 为 `ok` 的 JSON 并以退出码 `0` 结束。

## HTTP 服务

```bash
PYTHONPATH=src python3 -m science_strategy_foundation.api --database science_strategy.sqlite3 --host 127.0.0.1 --port 8080
```

健康检查使用 `GET /health`。写入接口通过 `X-Actor-Id` 标识操作者，所有写接口支持 `request_id` 幂等，服务重启后 SQLite 中的业务状态和审计历史继续保留。联合投入接口统一挂在 `/jv/...` 前缀下（平台、成员、章程、人才、设备、资金、计划、里程碑、承诺、会签、履约、异动、退出、成果权益、就绪与快照查询）。
